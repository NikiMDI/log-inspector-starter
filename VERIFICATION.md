# Проверка на ноутбуке

Фактический прогон выполнен 6 сентября 2026 года на Docker Engine 26.1.4 (Linux amd64).

## Результаты

- `docker compose --env-file env/dev.env run --rm --build test-runner` — успешно; все пакеты собраны с race detector, тесты анализатора и генератора прошли.
- Контрольный `fixtures/access.jsonl` — состояние `done`, JSON-отчёт совпал с `fixtures/expected.json` после числовой нормализации через `jq`.
- `fixtures/invalid.jsonl` — состояние `failed`, ошибка указывает строку 2; успешный частичный отчёт отсутствует.
- API через Nginx — проверены 202, 409 до готовности, 404 неизвестного ID, 415 неверного media type и JSON-ответ 413 при превышении лимита.
- Полный `docker compose down`/`up` без `-v` — готовый отчёт снова доступен (`total_requests=12`); при отдельном перезапуске `app` незавершённое задание стало `failed` с текстом `обработка прервана перезапуском`.
- Один worker — три задания обработаны последовательно. Два worker — два задания одновременно `running`, ещё два `queued`, затем все четыре `done`; в логах указаны worker 1 и 2.
- `SHOW POOLS` — пул `loginspector` работает в режиме `transaction`; в dev `default_pool_size=3`, `max_client_conn=30`.
- `DB_MAX_OPEN=1` в test — после 200 конкурентных GET получены `WaitCount=17` и ненулевой `WaitDuration`.
- Миграции — в отдельной БД применена только 001, добавлена строка, затем применена 002; строка сохранилась и получила `original_filename=''`, в `schema_migrations` записаны обе версии.
- Окружения dev/test/stage/prod — все Compose-конфигурации успешно разобраны; имена проектов, порты, worker, размеры пулов и уровни логирования различаются.

## pprof

Для эксперимента сгенерирован `generated/large.jsonl`: 1 000 000 строк, 120 509 855 байт. Профили снимались во время состояния `running` и сохранены в игнорируемом Git каталоге `output/`.

`heap-4.prof` показал около 2 МБ живой кучи. Это подтверждает, что исходные 120,5 МБ не загружаются целиком: генератор использует только 4 маршрута, 21 IP и 60 минут, поэтому карты агрегатов малы.

`allocs.prof` показал 111,39 МБ суммарных выделений. Основные места:

- `encoding/json.Unmarshal` — 39,51 МБ собственных и 80,51 МБ накопленных выделений;
- декодирование JSON-литералов — 20 МБ;
- `analyzer.Analyze` — 19,50 МБ собственных и 100,01 МБ накопленных выделений.

Профиль соответствует потоковому дизайну: на каждой строке создаются временные объекты JSON, но после обработки они освобождаются; постоянно живут только агрегаты и буфер scanner.
